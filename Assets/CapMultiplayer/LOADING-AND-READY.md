# 로딩 화면과 대기실 준비

## 사용 방식

- 대기실의 각 플레이어 줄에 준비 상태가 표시된다. 본인의 `준비 완료` 버튼을 누르고, 다시 누르면 취소한다.
- 방장을 포함한 현재 참가자 전원이 준비하면 방장의 `게임 시작` 버튼이 활성화된다. 방장이 버튼을 누르면 3초 카운트다운 후 시작한다. 전원 준비만으로 자동 시작하지 않는다. 혼자 테스트할 때도 준비 후 시작 버튼을 누른다.
- 카운트다운 중 준비를 취소하면 시작을 취소한다. 카운트다운 도중 참가·퇴장으로 인원이 바뀌면 준비 상태도 초기화하여, 남은 사람끼리 의도치 않게 시작하지 않도록 다시 준비를 누르게 한다.
- 새 참가자는 준비하지 않은 상태로 들어온다. 게임 시작 후 대기실로 돌아오면 모두 다시 준비해야 한다.
- 방 생성·참가·퇴장, 대기실 ↔ 마을, 마을 ↔ 회의실 이동에는 로딩 화면을 표시한다. 빠른 이동도 약 1초간 표시하고 마지막 0.3초 동안 화면을 드러낸다.
- 로딩 중 이동·상호작용·설정 조작을 막는다. 실제 연결이 진행 중이면 완료 또는 실패 처리까지 로딩을 유지하고, 실패 시 기존 메뉴에 오류 안내가 표시된다.

## 코드 구조

`CapLoadingScreen`은 연결 작업과 로컬 플레이어의 공간 상태를 확인한다. 마을 배경 및 카메라 업데이트 이후에 준비 여부를 판단해 화면이 바뀌는 순간을 가리고, 준비가 끝나면 실제 경과 시간을 기준으로 사라진다. 임의의 진행률 대신 점 애니메이션을 사용한다. 이동 권한을 가진 방장도 공간 전환 직후 잠시 입력을 제한한다.

`CapLobbyReady`의 준비 상태와 시작 시각은 방장이 관리하는 NetworkVariable이다. 플레이어는 자신의 준비 상태만 RPC로 요청할 수 있다. 방장이 시작 버튼을 누르면 준비 상태를 다시 검사한 뒤 시작 시각을 정한다. 방장은 접속 인원과 준비 상태를 매 프레임 확인하고, 서버 시간 기준으로 3초가 지나면 기존 마을 이동 함수를 호출한다. 각 클라이언트는 같은 시작 시각을 받아 남은 시간을 표시한다.

네트워크 변수 추가에 따라 프로토콜 버전은 4이다. 친구와 같은 최신 빌드를 사용한다.

## 검증 방법

개발 빌드에 `--loading-ready-verify`를 전달하고 방장에는 `--loading-ready-host`를 추가하면 두 실제 Relay 클라이언트로 전원 준비 후 대기, 방장 시작 권한, 취소, 참가자 변경, 3초 카운트다운, 로딩 중 이동 제한과 해제를 검증한다. 검증 실행에서는 마이크를 전송하지 않는다.
