# 새 마을 탐색 프로토타입

## 실행
1. CAP > 새 마을 대기실 열기 메뉴를 선택합니다.
2. Play를 누르고 인터넷 방 만들기 또는 참가 코드를 사용합니다.
3. 방장이 '게임 시작 · 마을로 이동'을 누르면 접속한 플레이어들이 함께 이동합니다.
4. 혼자도 방을 생성하여 시작할 수 있습니다. 인터넷 없이 점검하려면 개발용 로컬 테스트 > 로컬 Host를 사용합니다.

- WASD / 방향키: 이동
- 마우스 휠: 확대·축소
- M: 전체 마을 보기 / 캐릭터 따라가기
- 방장의 '대기실로 돌아가기': 모두 대기실 복귀
- 방장이 나가면 기존과 같이 세션이 종료됩니다.

## 구성
새로 제작한 밝은 색감의 건물 및 소품을 사용합니다. 대학 동아리 건물은 우측 상단, 큰 공원은 중앙, 주변에는 편의점·카페·병원·서점·세탁소·정비소·주거 건물을 배치했습니다. 건물 내부와 사건 콘텐츠는 아직 구현하지 않았습니다. 네 캐릭터에 앞·뒤·양옆·대각선의 8방향 걷기와 정지 포즈를 적용했습니다. 5가지 방향 원화와 좌우 반전으로 구성하며, 방향별 걷기 4프레임을 초당 8프레임으로 재생합니다. 이동을 멈추면 마지막 방향을 유지하며, 벽에 막혀 움직이지 않을 때도 걷기를 멈춥니다. 서버가 실제 이동 방향과 걷기 상태를 동기화합니다.

마을 전체를 한 장으로 확대하지 않습니다. Resources/WarmTown/catalog.json의 개별 사물 영역을 Sprite로 만들고 Runtime/CapWarmTown.cs에서 각각 배치합니다. 바닥은 반복 타일, 도로는 동일한 6유닛 폭의 왕복 2차로이며 보행자도 통행 가능합니다. 각 차로는 3유닛입니다.

마을은 Play 중 'Warm Town — modular environment' 계층에 생성됩니다. 대기실과 같은 씬에서 공간 좌표 및 표시 상태를 분리하여 기존 Relay 연결과 네트워크 플레이어를 유지합니다. 별도 씬 파일로 전환하는 구조는 아닙니다. 편집 모드의 대기실 화면은 그대로입니다.

충돌은 사물 밑면을 기준으로 제한하며 플레이어 발 위치에 따라 렌더 순서를 조정합니다. Sprite 알파가 반투명하게 남는 생성 이미지 특성을 보정하기 위해 PixelSprite 셰이더로 불투명 부분을 처리합니다.

## 파일
- Runtime/CapWarmTown.cs: 배치, 충돌, 카메라, 게임 단계 전환
- Runtime/CapNetworkPlayer.cs: 서버 이동, 단계 동기화, 캐릭터 정렬
- Resources/WarmTown: 원본 PNG, Sprite 영역표, 렌더링 셰이더
- Editor/CapWarmTownSetup.cs: 이미지 Import 설정과 Windows 빌드
- Runtime/CapTownSmoke.cs: 개발 빌드에서 명시적 인자가 있을 때만 실행되는 자동 검증
- Builds/CapWarmTown/cap.exe: 실행 파일. 친구에게 보낼 때는 폴더 전체 또는 ZIP을 전달합니다.
