# 조작키와 인터넷 음성 채팅

## 사용법

- 시작 화면의 **옵션**, 또는 게임 중 **F10**으로 설정을 연다.
- **조작키 변경**에서 원하는 항목을 클릭한 뒤 새 키를 누른다. Esc는 변경 취소다. 중복 키는 거부하며, 기본값으로 초기화할 수 있다.
- 기본 조작: W/A/S/D 이동, M 지도, B 자전거, V 눌러서 말하기, N 마이크 음소거. Esc와 F10은 예약 키다.
- **음성 채팅**에서 음성 사용, 눌러서 말하기/항상 켜짐, 마이크 음소거, 친구 목소리 음량, 마이크/스피커를 설정한다. 장치 선택란을 누르면 드롭다운 목록이 펼쳐진다. 현재 장치에는 체크 표시가 붙으며, 원하는 장치를 직접 선택한다. 장치가 많으면 목록을 스크롤한다. 바깥을 누르거나 Esc를 누르면 목록이 닫힌다.
- 입력 방식은 **항상 켜짐**과 **눌러서 말하기** 중 하나를 선택하며, 선택된 항목에 색상과 ● 표시가 붙는다. 항상 켜짐은 키 없이 송출하고, 눌러서 말하기는 설정한 키를 누르는 동안만 송출한다. 처음에는 V를 누르는 동안만 마이크를 송출한다. 마이크 음소거는 두 방식 모두보다 우선한다. 설정 창이 열려 있거나 게임 창이 포커스를 잃으면 송출을 멈춘다.
- 게임 창 아래쪽에 연결 상태와 마이크 상태를 표시한다. 연결 실패 시 음성 설정에서 재연결할 수 있다.
- 플레이어 설정은 각 컴퓨터의 PlayerPrefs에 저장하며 Git으로 공유하지 않는다.

## 장치 설정과 연결 복구

시작 화면·대기실·마을 어디에서 옵션을 열어도 장치 목록을 준비한다. 방을 만들기 전에는 음성 채널에 들어가지 않으며 마이크를 송출하지 않는다. 최초 장치 준비에는 Unity 서비스 초기화가 필요하므로 인터넷 연결을 사용한다.

스피커와 마이크의 기본값은 **시스템 기본 장치 (자동)**이다. Windows 기본 출력/입력 장치를 바꾸면 Vivox가 해당 장치를 따라가며 선택란에 실제 장치 이름을 표시한다. 특정 장치를 직접 선택하면 그 선택을 저장한다. 자동으로 돌아가려면 목록 맨 위의 시스템 기본 장치를 선택한다. 저장된 장치가 없으면 시스템 기본 장치로 대체한다.

음소거는 SDK 응답 전에 같은 요청을 반복하지 않도록 CapVoiceMuteGate에서 관리한다. 응답이 5초 동안 없으면 음성 처리를 중지하고 10초 후 연결을 초기화해 재시도한다. 음량 요청은 값이 바뀔 때만 최대 초당 10회 전송한다. SDK의 네트워크 복구 중에는 별도 재연결을 겹쳐 실행하지 않는다.

## 음성이 들리는 규칙

마을에서는 **일반 게임 카메라 화면 안에 상대 캐릭터 중심이 있을 때만** 목소리를 재생한다. 캐릭터끼리 2.5 월드 단위 이내에서는 기본 음량이며, 더 멀어질수록 줄어든다. 화면 가장자리 5%에서도 음량을 줄여 경계에서 갑자기 큰 소리가 나지 않게 했다. 화면 밖이면 즉시 음소거한다. 벽에 의한 차단은 포함하지 않는다.

대기실에서는 거리에 관계없이 대화한다. 대기실과 마을처럼 서로 다른 공간에 있으면 들리지 않는다. 지도는 별도의 정적 사진이므로 지도를 열어도 들리는 범위가 늘어나지 않는다. 현재 회의 단계는 아직 없으며, 추후 회의 상태가 추가되면 대기실처럼 전체 대화 규칙으로 연결한다.

이 규칙은 **각 수신자의 화면 기준**이다. 화면 비율이나 위치에 따라 한쪽에게만 상대가 보이면 한쪽만 들을 수도 있다. 또 음량 제한은 클라이언트 재생 규칙이며, 변조된 클라이언트의 도청까지 막는 서버 권한 정책은 아니다.

## 구조를 설명하는 방법

1. `CapRelaySession`: Unity Authentication으로 로그인하고 Multiplayer/Relay 방을 만들거나 참가한다. 방의 세션 ID를 음성 채널 식별자로 사용한다.
2. `CapVoiceChat`: 같은 세션 ID를 가진 사람을 같은 Vivox 음성 채널로 연결한다. 연결이 끊기거나 방에서 나가면 음성을 정리하며, 마이크와 음량을 제어한다.
3. `CapNetworkPlayer.VoicePlayerId`: 게임 캐릭터와 Vivox 참가자를 연결하는 Authentication Player ID를 동기화한다. 연결 전에는 해당 참가자를 음소거한다.
4. `CapVoiceRange`: 카메라 화면 포함 여부와 캐릭터 간 거리를 계산해 0~1의 재생 음량을 결정한다. `CapVoiceChat`이 이를 각 Vivox 참가자의 로컬 음소거/음량에 적용한다.
5. `CapControls`: 키 설정을 한곳에서 관리한다. 이동, 자전거, 지도, 음성 기능과 화면 안내가 같은 설정을 참조한다.
6. `CapOptions`: 세 가지 설정 탭을 그린다. 열려 있는 동안 로컬 이동과 단축키 입력을 막는다. 다른 플레이어는 계속 움직인다.

Relay는 이동 등 게임 데이터를 중계하고, **음성 데이터는 Unity Vivox 관리형 서버**가 처리한다. 별도의 개인 서버나 포트 포워딩은 필요하지 않다. 모든 참여자는 같은 최신 게임 빌드를 사용해야 한다.

## 프로젝트 설정과 팀원 공유

- Unity 6000.3.23f1, Vivox SDK 16.12.1을 사용한다.
- `Packages/manifest.json`, `Packages/packages-lock.json`, `ProjectSettings/Packages/com.unity.services.vivox/Settings.json`, 변경된 스크립트와 `.meta`를 함께 공유한다.
- 설정 파일의 서버, 도메인, 발급자는 공개 접속 식별자다. **토큰 키는 비워 두며 Test Mode를 사용하지 않는다.** 인증 토큰은 Unity Authentication을 통해 발급한다.
- Unity Cloud 프로젝트를 바꾸면 Services > Vivox에서 새 프로젝트의 접속 설정을 다시 가져와야 한다.
- 로컬 접속 테스트에는 인터넷 세션 ID가 없으므로 자동 음성 접속을 하지 않는다. **시작 화면의 방 만들기/방 참가하기**로 테스트한다.

## 친구와 최종 확인

### 음성 증폭과 거리 (2026-10-04)

- 옵션 → 음성 채팅 → 친구 목소리 음량: 0~200%. 기본값은 100%이며 기존 저장값을 유지한다. `100% 복원` 버튼으로 기본 크기로 돌아간다.
- 100% 초과는 받는 사람의 음성 출력에 증폭을 적용한다. 상대방의 마이크 설정을 변경하지 않는다. 200%에서 Vivox 출력 조정값은 +6이며, 거리별 참가자 감쇠는 별도로 유지한다. 0%에서는 출력 음소거를 사용한다.
- 마을의 최대 청취 거리와 일정한 크기로 들리는 근거리 영역을 모두 이전의 50%로 줄였다. 근거리는 2.5 → 1.25 Unity 단위, 최대 거리는 일반 카메라 반대각선 길이의 절반이다. 화면 밖과 서로 다른 공간은 계속 무음이며, 대기실은 전체 대화를 유지한다.
- 장치 테스트의 스피커 소리에도 200%까지 동일한 선형 배율을 반영한다. 실제 말소리의 체감 크기는 상대 입력과 장치에 따라 달라진다.

SDK 출력 조정 범위: [Unity Vivox 오디오 레벨](https://docs.unity.com/en-us/vivox-unity/developer-guide/in-game-audio-control/in-game-control-audio-levels).

### 내 장치 먼저 확인하기

시작 화면, 대기실, 마을의 옵션에서 **장치 테스트** 탭을 연다. 이 탭에서도 마이크와 스피커 드롭다운으로 장치를 변경할 수 있다.

- **마이크 테스트 시작**: 실제 입력 소리 크기가 막대에 표시된다. 로컬 테스트이므로 게임 내 음소거/눌러서 말하기 설정과 별개로 입력을 확인하며, 친구에게 보내거나 파일로 저장하지 않는다. 30초 뒤 자동 종료한다.
- **스피커 소리 테스트**: 선택한 출력 장치로 짧은 두 음을 재생한다. 전체 음량과 친구 목소리 음량을 반영하며, 음량이 0이면 먼저 올리라는 안내를 표시한다.
- 설정 닫기, 탭 변경, 장치 변경, 창 포커스 상실, 음성 재연결 시 테스트를 중지한다. 두 테스트는 동시에 실행하지 않는다.
- 입력 막대는 마이크에 소리가 들어오는지 확인하는 용도이며, Vivox 서버 전송 성공이나 상대방 수신을 보증하지 않는다. 실제 통화는 아래 친구와 확인 절차로 검사한다.

현재 Windows용 `CapAudioDeviceTest`가 WinMM으로 로컬 장치를 검사한다. Vivox의 EffectiveInputDevice/EffectiveOutputDevice ID를 Windows endpoint ID와 정확하게 비교하여 선택한 장치를 연다. Unity AudioSource의 기본 출력으로 우회하지 않으며, 장치가 없으면 다른 장치로 몰래 전환하지 않고 실패를 표시한다. 마이크 PCM은 짧은 메모리 버퍼에서 RMS를 계산한 뒤 재사용하고 종료 시 해제한다. 막대의 0~100%는 -60~0 dBFS 범위를 표시한 입력 크기이며 마이크 감도 설정값이 아니다. 테스트용 음원은 코드로 생성하므로 추가 에셋/서비스가 필요 없다.

구현 근거: [Microsoft의 오디오 endpoint 매핑](https://learn.microsoft.com/en-us/windows/win32/coreaudio/device-roles-for-legacy-windows-multimedia-applications), [Unity Vivox 장치 선택](https://docs.unity.com/en-us/vivox-unity/developer-guide/in-game-audio-control/in-game-audio-device-selection).

개발 빌드에 `--audio-device-verify` 인자를 주면 장치 초기화, 로컬 입력 버퍼 수신, 선택 출력 장치의 무음 버퍼 재생/해제, 테스트 종료 동작을 검사한다. 검사 결과만 저장하며 마이크 소리를 녹음 파일로 저장하거나 송출하지 않는다.

1. 서로 다른 PC에서 같은 방에 입장한다. 헤드셋을 권장한다.
2. 하단에 음성 연결됨이 표시되면 V를 누르며 말한다. N으로 음소거했을 때 상대에게 들리지 않는지 확인한다.
3. 마을에서 가까이, 멀리, 화면 밖 순으로 이동하며 음량과 차단 여부를 확인한다.
4. 지도를 열어도 청취 범위가 늘어나지 않고, 대기실로 돌아가면 모두 들리는지 확인한다.
5. 음성이 안 들리면 음소거와 출력 음량, 선택한 장치, Windows의 데스크톱 앱 마이크 접근 허용을 확인한다.

자동 검증은 실제 Relay/Vivox 연결과 참가자 음량/음소거 상태를 확인한다. 테스트에서는 마이크를 송출하지 않으므로 실제 말소리 품질, 장치별 음량, 에코는 위 절차로 확인해야 한다.

## 검증 기록 (2026-10-03)

Windows 빌드 성공(컴파일 오류 0개). 두 실행 파일이 실제 Relay/Vivox 방에 접속하여 ID 연결, 대기실 전체 음성, 근거리/원거리 음량, 화면 밖 음소거, 재진입 복구, 서로 다른 공간의 차단, 지도 열람 중 청취 범위 유지, 방 퇴장 후 음성 종료 검증을 통과했다. 시작 메뉴 및 대기실/마을 전환 회귀 검사도 통과했다.

두 사람이 동시에 퇴장하는 시험에서는 기존 Multiplayer SDK 1.2.0의 Lobby 이벤트 처리에서 중복 키 및 삭제된 로비 조회 예외가 기록되었다. 해당 시험의 퇴장과 음성 종료는 완료됐으나, 이 SDK 종료 경합은 남아 있는 확인 사항이다. SDK 내부 파일을 임의로 수정하거나 로그를 숨기지는 않았다.
