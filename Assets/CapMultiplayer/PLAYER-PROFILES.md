# 플레이어 번호와 프로필

- 대기실의 **내 플레이어 줄(변경 ▸)**을 누르면 목록 옆에 편집 창이 열린다. 이름과 색상을 선택하고 **적용 / 저장**을 누른다. 옵션에는 프로필 탭을 두지 않는다. 다른 사람의 줄은 편집할 수 없다.
- 이름을 입력하는 동안 이동·자전거·음소거 단축키와 마이크 송출을 막는다. Esc 또는 닫기로 창을 닫으면 조작이 복구된다. 퇴장하거나 게임이 시작되면 편집 창도 닫힌다.
- 이름은 최대 12자이며 한글·영문 등 문자, 숫자, 공백, `_`, `-`를 허용한다. 빈 이름은 `P1` 같은 번호로 표시한다. 같은 이름도 허용하되 P번호로 구분한다.
- 도형 캐릭터의 색상은 8가지다. 현재 방에서 사용 중인 색은 선택할 수 없다. 두 사람이 동시에 같은 색상을 요청해도 방장이 한 명에게만 허용한다.
- 입장 시 저장한 색이 이미 사용 중이면 빈 색을 자동 배정한다. 기존 플레이어의 번호와 색상은 바뀌지 않는다. 자동 대체 색으로 개인의 저장된 선호 색을 덮어쓰지 않는다.
- 재입장 시 이전 번호를 계정에 예약해 두지는 않는다. 방장이 현재 비어 있는 가장 작은 P번호를 배정한다. P번호는 네트워크 ClientId와 별개이며, ClientId를 4로 나눈 값으로 표시하지 않는다.

## 코드 구조

`CapNetworkPlayer.PlayerSlot`, `ColorIndex`, `Nickname`은 방장만 수정할 수 있는 NetworkVariable이다. 번호 배정 시 현재 스폰된 플레이어만 검사하므로 퇴장한 자리는 다시 사용한다. 색상·이름 변경 RPC는 소유자만 요청할 수 있고, 방장이 범위와 중복을 확인한다. 변경 결과를 받은 소유자가 PlayerPrefs에 저장한다.

캐릭터 렌더링, 대기실 목록, 지도 마커가 동일한 ColorIndex와 Nickname을 사용한다. P번호는 생성 위치에도 사용하지만 네트워크 소유권과 음성 참가자 식별은 기존 ClientId/인증 ID를 유지한다.

네트워크 필드 구성이 변경되어 프로토콜 버전은 2이다. **방장과 참가자 모두 같은 최신 빌드를 사용해야 한다.**

## 재접속 검증

개발 빌드를 `--slot-verify --slot-role host/one/two/cycle`로 각각 실행하는 `run-slot-verification.ps1`이 네 개의 실제 NGO 프로세스를 연결한다. 로컬 전송을 사용하여 세 명이 남아 있는 상태에서 네 번째 클라이언트를 여섯 번 재접속시키고, P번호·색상 중복, 이름 동기화, 마을/대기실 복귀와 색상 선점 경합을 검사한다. 이 검증 모드는 개인 프로필 설정을 저장하지 않는다.
