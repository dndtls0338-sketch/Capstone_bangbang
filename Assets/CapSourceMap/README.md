# 원본 배율 마을 조립

## 기준

- 화면 기준: `convenience-store-no-ui.png`, 1534 × 1025.
- 캐릭터 높이: 기준 화면에서 약 90픽셀, 월드에서 1.80.
- 카메라: Orthographic Size 10.25, 원본 화면비 유지. 창 비율이 다르면 레터박스 적용.
- 카메라는 로컬 플레이어의 실제 렌더링 경계 중심을 따라간다. 가장자리에서도 플레이어를 화면 바깥쪽으로 밀어내는 카메라 클램프를 사용하지 않는다.
- 배치 좌표: 승인한 전체 마을 이미지의 1536 × 1024 좌표. 배치 이미지의 1픽셀은 원본 화면의 3.5픽셀에 대응한다.
- 편의점 본체 폭: 배치 좌표 145.4 → 화면 약 509픽셀. 건물마다 가로·세로를 다르게 늘리지 않는다.

## 에셋

`Resources/SourceMap`은 승인된 개별 PNG를 그대로 복사한 것이다. 다시 생성하거나 확대 저장하지 않는다.
`CapSourceTown.SourceSlice`가 건물 본체·진열대·쓰레기통·벤치 등을 원본 사각 영역으로 분리한다. 원본 PNG를 수정하지 않는 Unity Sprite 분할 방식이다.
도로와 보도는 편의점 원본의 빈 표면을 반복하며, 나머지 소품은 기존 투명 에셋을 재사용한다.
`Assembled/SourceSprites.asset` 안에는 개별 Sprite 하위 에셋이 들어 있고, `SourceTown.prefab`에서 각각 위치와 크기를 조정할 수 있다.
편집용 프리팹과 멀티플레이 실행용 좌표 데이터는 별도다. 프리팹에서 바꾼 위치를 게임에 영구 반영하려면 `CapSourceTown.cs`의 해당 좌표도 수정해야 한다.

## 실행

기존 `Assets/CapMultiplayer/Scenes/CapRelayTest.unity`를 사용한다.
대기실에서 방 생성/참가 후 게임 시작 → 마을. WASD/방향키 이동, M 전체 배치 보기, B 기존 자전거 기능.
휠 줌은 배율이 바뀌지 않도록 비활성화했다. M을 다시 누르면 고정된 플레이 화면으로 돌아온다.
M 전체 지도에서 대기실 복귀 버튼을 사용할 수 있다.

## 범위

이번 결과는 원본 개별 에셋과 승인 배치 좌표를 사용한 조립본이다. 승인한 전체 마을 이미지와 픽셀 단위로 동일한 복원은 아니다.
그 전체 이미지에서 새로 그려진 세부 건축 형태와 승인된 개별 에셋이 서로 다르므로 일부 외형과 장식에는 차이가 있다.
배경에 그려진 사람은 가져오지 않았으며, 실제 네트워크 플레이어를 별도로 표시한다.
실내, 사건·NPC 대화 시스템은 이번 작업에 추가하지 않았다.

## 검증

`SourceMapVerification`은 개발 빌드에서 카메라 중앙 정렬, 주요 지점 충돌, 이동 및 대기실 복귀를 검사하고 1534 × 1025 스크린샷을 남긴다.
이 검사는 외부 인터넷 Relay 접속 검사를 대체하지 않는다.
